## 1. 要修的三处判据问题（这才是本轮的真实缺陷）

### 1.1 空断言（最重要）
`tools/run_pcg_chain.py::_run_real_multi`：

```python
failed = [k for k, v in mats.items() if isinstance(v, dict) and v.get("ok") is False]
checks.append(("材质编译 failed == 0", not failed, ...))
```

而 `ue/Content/Python/check_material_compile.py` 写出的每条材质只有
`class / blend / recompile / parent` **四个字段，从来没有 `ok`** →
`failed` 恒为空 → 只要证据 JSON 存在，这条断言 **100% PASS，等于没判**。

### 1.2 编译子进程退出码没进判据
`--with-compile` 的 `_run("6/7 UE 双树种材质编译复检", ...)` 之后没有检查 `p.returncode`。
现在能 FAIL 只是碰巧因为崩溃导致证据 JSON 没写出来；**如果崩溃发生在证据落盘之后，就会假 PASS**。

### 1.3 证据文件污染工作区
`--with-compile` 写 `docs/material_compile_check_pair.json`，既不在 `.gitignore` 也不是交付产物，
跑一次必脏工作区（复验时就得手动 `git restore`）。
