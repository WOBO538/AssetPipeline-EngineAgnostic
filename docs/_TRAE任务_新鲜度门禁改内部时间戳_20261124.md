# TRAE 任务单 9：把 `--parity-check` 的新鲜度门禁改成比内部时间戳（v1.11）

> 下发：2026-11-24 15:00（lead）
> 仓库：`D:\Projects\AssetPipeline-EngineAgnostic`
> 基线：**`3c76cbd`**（v1.10.1，lead 已复验：生成器双分支、断言 5 四方向有牙齿、重生成报告与入库版逐字节相同、perf JSON 一字节未变）
> 目标版本号：v1.11
> 起因：TRAE 在 v1.10.1 如实报告的 `--parity-check` FAIL —— **门禁用文件 mtime 比较证据新鲜度**，跨 clone/checkout 不可靠

---

## 0. 问题（lead 已复现）

```
$ python tools/run_pcg_chain.py --parity-check
CHAIN FAIL: 证据早于 manifest（不新鲜）：docs\placed_tree_multi_verify.json | schemas\tree_manifest_multi.unity_placements_verify.json
```

实测 mtime：manifest `13:33:39`、UE 证据 `13:33:39`、Unity 证据 `13:33:33` → Unity 证据被判"旧 6 秒"。

**根因两层**：

1. 门禁拿 `os.path.getmtime()` 比较——**git clone / checkout 会把所有文件 mtime 重置成克隆时间**，顺序随机，这个门禁在任何新环境里都可能直接挂；
2. Unity 侧读回 JSON **没有内部时间戳字段**（`unity_verify.json` / `unity_placements_verify.json` 都没有 `when`/`generatedAt`），所以即便想改也无据可依。

现状的内部时间戳：

| 文件 | 内部时间戳 |
|---|---|
| `schemas/tree_manifest_multi.json` | `generatedAt = 2026-11-24T13:05:38+08:00` ✅ |
| `docs/placed_tree_multi_verify.json`（UE 读回） | `when = 2026-11-24T13:06:16` ✅ |
| `schemas/tree_manifest_multi.unity_placements_verify.json`（Unity 读回） | **无** ❌ |

---

## 1. 红线

1. 不许改 mtime 凑 PASS（`touch`/`Set-ItemProperty` 一律禁止）；不许把证据时间戳伪造成"新"；
2. 五条门槛不变：13 / 20 / 21 / 4 / 4；`--perf` 与断言 5 不动；
3. `--parity-check` 的 4 条对账断言与容差（0.01 m / 0.05° / 1e-3）一个字不改；
4. manifest 与证据 JSON 的既有字段名不动，只允许**新增**时间戳字段。

---

## 2. 要做的事

### A. Unity 侧补内部时间戳

`unity/Editor/ManifestImporter.cs`：

- `VerifyFromArgs`（`unity_verify.json`）与 `VerifyPlacementsFromArgs`（`unity_placements_verify.json`）都写入
  `"generatedAt": "<ISO8601 带时区偏移>"`，例如 `2026-11-24T15:02:11+08:00`；
- 时区取本地偏移（`DateTimeOffset.Now.ToString("yyyy-MM-dd'T'HH:mm:sszzz")`），**不要用 UTC 冒充本地**，也不要只写 `DateTime.UtcNow` 不带偏移；
- 原有字段只增不改。

### B. `--parity-check` 新鲜度门禁改成比内部时间戳

`tools/run_pcg_chain.py`：

1. 读 manifest 的 `generatedAt`、UE 证据的 `when`（或 `generatedAt`）、Unity 证据的 `generatedAt`；
2. 三者都解析成带时区的 datetime（缺失/无法解析 → **FAIL，并明确写"缺内部时间戳，无法判定新鲜度"**），**不再**回退到 mtime；
3. 判定：`证据时间 >= manifest 时间` 才算新鲜（同一秒允许相等）；
4. 报错信息里同时给出三方内部时间戳原文，便于排查（例如 `manifest=...T13:05:38+08:00 ue=...T13:06:16 un=...T15:02:11+08:00`）；
5. 保留一个**只用于反验**的环境变量 `EAP_PARITY_IGNORE_FRESHNESS=1`，默认关闭。

### C. 迁移现有证据

- 重新跑 `--unity-placements-check`（需要 Unity 关闭状态），让 Unity 证据带上 `generatedAt`；`--unity-check` 同理顺手更新；
- 证据 JSON 若入库需一并提交（新增字段，其余不动）。

```bash

# 期望：4/4 PASS（不再报"证据早于 manifest"）

# 2) 五条老门槛不变
python tools/run_pcg_chain.py --multi --expect-assets 20
python tools/run_pcg_chain.py --real-multi --with-compile --expect-assets 2 --expect-placements 1892
python tools/run_pcg_chain.py --unity-check --unity "..." --unity-project "D:\unity\EAP_Unity_Consumer" --manifest schemas\tree_manifest_multi.json
```

**反向验证（三条，都必须做）**：

1. **mtime 无关性**：把 Unity 证据文件 mtime 改成比 manifest 早 1 小时（`(Get-Item f).LastWriteTime = ...`，**只改 mtime 不改内容**）→ `--parity-check` 必须仍 **PASS**（证明门禁已不看 mtime）；改完还原 mtime；
2. **内部时间戳过期**：把 Unity 证据的 `generatedAt` 改成比 manifest 早 1 小时（只改副本，放在 `%TEMP%`，用 `--parity-from` 之类的方式喂入；若没有该开关，就临时改工作区副本、跑完 `git checkout` 还原）→ `--parity-check` 必须 **FAIL** 且报错里带三方时间戳；
3. **缺时间戳**：删掉 Unity 证据的 `generatedAt` → 必须 **FAIL**（"缺内部时间戳"），不许静默回退 mtime。
