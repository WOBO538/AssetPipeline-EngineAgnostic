# Lead 复核：v1.6 roughness 是否真的生效（UE 粗糙度缓冲区，2026-11-23 22:07）

## 背景

v1.6 交付（commit `c18b8e2`）声称 roughness 走贴图，但数据判据只到"MIC 参数读回"。lead 用 UE 视口 **视图模式 → 缓冲区可视化 → 粗糙度** 做视觉复核，过程踩了两个坑，结论如下。

## 坑 1：看错关卡（不是 roughness 失效）

前两次缓冲区截图取自 **`/Game/EAP/PCG/PlacedTrees`**（v1.2/v1.3 遗留关卡，材质是 v1.5 之前的常量 roughness=0.9），直方图恒定：

```
PlacedTrees 粗糙度缓冲：px p10=0.894 p50=0.897 p90=0.899（重启编辑器后仍然一样）
```

这正好等于老材质的标量 0.9——**不是 bug，是测错了对象**。链路的 `--real-multi` 实际使用的关卡是 **`/Game/EAP/PCG/PlacedTreeMulti`**（`docs/placed_tree_multi.json` 的 `levelPackage` 字段，1892 实例）。

## 坑 2：`stage()` 在真编辑器里跑会报错（UE 5.7 API 签名）

为了给 `PlacedTreeMulti` 补灯光，lead 让用户跑：

```
import sys, importlib; sys.path.insert(0, r"D:\Projects\AssetPipeline-EngineAgnostic\ue\Content\Python"); import place_manifest; importlib.reload(place_manifest); print(place_manifest.stage("/Game/EAP/PCG/PlacedTreeMulti", None, True))
```

灯光（DirectionalLight / SkyLight / SkyAtmosphere / ExponentialHeightFog）**全部加成功**，但地面那步抛异常：

```
File ".../place_manifest.py", line 1271, in stage
TypeError: set_actor_location() required argument 'teleport' (pos 3) not found
```

原因：UE 5.7 Python 的 `Actor.set_actor_location(new_location, sweep, teleport)` 需要 **3 个参数**，v1.2 时代写的代码只传了 2 个。因为异常，后面的 `save_map` 没执行，编辑器报保存失败。
→ **待修**（属 `place_manifest.py::stage()`，等任务单 5 交付后单独修，避免与 TRAE 并发改同一文件）。

## 结论：v1.6 的 roughness 确实生效

在正确关卡 `PlacedTreeMulti` 上，粗糙度缓冲区两个视角的像素直方图：

| 视角 | 像素数 | mean | p10 | p50 | p90 |
|---|---|---|---|---|---|
| 近景 | 854,206 | 0.677 | 0.639 | 0.665 | 0.697 |
| 远景 | 755,503 | 0.672 | 0.659 | 0.667 | 0.697 |

- 数值落在 **0.61–0.74** 区间，与「针叶 roughness 贴图 mean 0.677 / 阔叶 0.731」同一量级，**不再是恒定 0.9**；
- 直方图有明显分布（不是单峰一根线），说明贴图确实被采样；
- 与旧关卡（恒定 0.894–0.899）形成对照。

## 残留（诚实记录）

1. **视觉幅度仍弱**：树皮 0.764 vs 树叶 0.677/0.731，缓冲区上差 ~0.06–0.08，肉眼在光照视图里几乎看不出。要明显的话需把合成区间拉大（如 0.95 / 0.55），代价是 4 张 roughness PNG 的 SHA 与三条断言同步更新。
2. `stage()` 的 `set_actor_location` 参数 bug 待修；修好后 `PlacedTreeMulti` 才能一键补齐灯光+地面并保存。
3. `PlacedTrees` 是 v1.2 遗留关卡（6 Actor，旧材质），可列入后续清理清单，暂不删。
