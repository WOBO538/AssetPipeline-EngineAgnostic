# 故障库文风公约

> 目标：读起来像工程师写的工单/复盘，不像 AI 写的说明文。
> 反面样本（改前的版本、以及作品集现在部分文案）：长句 + 因果链 + 每条都"这说明了X"。

## 规则

1. **第一人称，写我做了什么**："我加了一条断言"/"我一开始判断错了"，不写"该方案实现了…"。
2. **一句一件事**。超过 40 个字就断成两句。
3. **先写动作和数字，再写结论**；不要先给结论再解释为什么。
4. **允许承认判断错误**：写"我以为是 X，结果是 Y"比写"经过排查定位到 Y"可信。
5. **禁用词**：本质上、核心在于、值得注意的是、赋能、闭环、生态、显著、极大、深入、全方位、助力、不仅…而且、无论是…还是、正如、综上所述、值得一提的是。
6. **不要排比三连**（"既要…又要…还要…"），不要为了节奏加破折号。
7. **每段不要都用"这说明"收尾**。
8. 表格只放数字和事实；解释放正文。

## 正面样本（Kimi 写的，2026-11-24，直接可用）

> 我一开始以为是贴图没挂。打开树逐项看材质和贴图，才发现是白模。回头查无头日志，确实没有编译失败。

> -nullrhi 下 UE 不真正编译材质，材质图写错也不报错。原链路只证明流程跑完了。

> 导入完成不代表材质编译发生。无头能验数据，不能验"编译真的发生了"。

## 负面样本（同样内容，AI 腔版）

> 该方案在无头环境下完成了材质编译流程，但由于缺少真实 RHI 上下文，无法验证材质编译的实际发生，导致假 PASS 的产生。

问题：主语是"该方案"不是"我"；"由于…导致…"套娃；一句话三个从句；结论放在最后没有动作。
