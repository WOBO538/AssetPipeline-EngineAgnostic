## 0. 一句话目标

产出一张**可复现、可追溯**的三段性能表（**导入 / 材质 / 碰撞**），每段 20 个资产、每段重复 ≥3 次，原始每次采样落盘为 JSON，README 只放汇总表 + 方法说明。

**这不是"跑个秒表写个数字"**——每一段必须有明确的计时边界（从哪到哪）、明确的 20 资产定义、以及冷/热 DDC 区分。

---

## 1. 红线

1. 既有五条断言门槛**一条都不许变**：`--multi` 13、`--real-multi` 20、`--with-compile` 21、`--unity-check` 4、`--unity-placements-check` 4、`--parity-check` 4；
2. v1.6–v1.9 的行为/资产/证据字段不动；
3. 性能数据**只记录、不设绝对阈值**（机器相关，"必须 < 2 秒"这类断言一律不许写）；
4. 不许把本机温度/后台负载带来的异常值删掉——异常值保留并在报告里说明。

---

## 2. 三段的口径（必须先写清，再计时）

| 段 | 计时边界（从哪到哪） | 20 资产定义 |
|---|---|---|
| **A. 导入** | UE `Interchange` 导入一个 glb 文件 → 返回资产对象（不含后续材质规范化） | **同一棵树 glb 的 20 个副本**（命名为 `perf_import_00..19.glb`，内容逐字节相同；副本用脚本从 `assets/raw/trees/conifer.glb` 复制，产物放 `$env:TEMP\eap_perf\` 不入库） |
| **B. 材质** | 对 20 个资产各建 2 个材质槽：母材质复用 + MIC 创建 + 贴图参数 + 压缩设置（`_normalize_materials` 等价路径） | 上述 20 个导入出来的资产 |
| **C. 碰撞** | **Unity 侧**：给 20 个 prefab 各加 `MeshCollider(convex)` + `Physics.BakeMesh` 等价步骤；**UE 侧**：ISM 碰撞启用 + 读回（可单列一列，不混进同一数字） | 20 个 prefab（Unity）/ 1,892 实例 ISM（UE），两列分开写 |

**冷/热 DDC**：每段至少各跑一次「冷」（先删 `D:\UECache` 里对应缓存或用 `-ddc=NoShared`，具体做法写进脚本注释与报告）与一次「热」，报告里分两列。冷热差不做断言。

**重复次数**：每段每状态 **3 次**，取 p50 与 min/max 一起写；3 次都失败则该段 FAIL。

---

## 3. 新命令 `--perf`

```
python tools/run_pcg_chain.py --perf --unity "<Unity.exe>" --unity-project "D:\unity\EAP_Unity_Consumer"
```

- 跑完输出 `docs/perf_2026xxxx_<hhmm>.json`（每次采样一行：`segment/round/cold_warm/duration_s/machine`，机器信息含 CPU/GPU/RAM/UE 版本/Unity 版本/日期）**入库**；
- `docs/perf_report.md`（汇总表）**入库**；
- 断言（4 条，只查"记录完整、数字自洽、可复现"）：
  1. 三段 × 冷热 × 3 次采样齐全（12 条 per UE-side segment，Unity 侧另计）；
  2. 每次采样 `duration_s > 0`；
  3. 汇总表 `min ≤ p50 ≤ max`；
  4. 二次运行生成的 `perf_report.md` 里**方法说明段落存在**（防"只贴数字不写口径"）。
- 断言 FAIL 时退出码非零。

---

## 4. 报告必须写的内容（README 新增「三之十二、性能」+ `docs/perf_report.md`）

1. 机器与版本：CPU/GPU/RAM/UE 5.7 build/Unity 2022.3.62f3c1、日期、DDC 路径；
2. 每段的**计时边界**（照第 2 节的表写，不许含糊成"导入大约"）；
3. **20 资产的真实定义**（同源 glb 副本 / 合成 fixture），以及"这不等于 20 个不同资产"的坦白说明；
4. 冷/热两列 + 每次原始采样（JSON 链接）；
5. **已知噪音源**：DDC 状态、后台进程、笔记本温度墙、Nanite 首次编译着色器；
6. 一句"这些数字只对本机配置有效，换机器需重跑 `--perf`"。

## 5. 自验

```bash
python tools/run_pcg_chain.py --multi --expect-assets 20
python tools/run_pcg_chain.py --real-multi --expect-assets 2 --expect-placements 1892
python tools/run_pcg_chain.py --real-multi --with-compile --expect-assets 2 --expect-placements 1892
python tools/run_pcg_chain.py --unity-check --unity "..." --unity-project "D:\unity\EAP_Unity_Consumer" --manifest schemas\tree_manifest_multi.json
python tools/run_pcg_chain.py --unity-placements-check --unity "..." --unity-project "D:\unity\EAP_Unity_Consumer" --manifest schemas\tree_manifest_multi.json
python tools/run_pcg_chain.py --parity-check --unity "..." --unity-project "D:\unity\EAP_Unity_Consumer" --manifest schemas\tree_manifest_multi.json
python tools/run_pcg_chain.py --perf --unity "..." --unity-project "D:\unity\EAP_Unity_Consumer"
python tools/validate_manifest.py schemas\tree_manifest_multi.json
```

**反向验证**：把 `--perf` 的某段采样写死成同一个值（临时改脚本，不提交）→ 断言 3（`min≤p50≤max` 与"3 次齐全"）必须 FAIL；恢复后 PASS。**这条能证明性能断言不是空判据。**
