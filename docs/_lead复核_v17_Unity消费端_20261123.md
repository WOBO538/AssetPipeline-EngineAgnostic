## 3. 负向测试（lead 自己做，独立于 TRAE 的说法）

清态：删掉 `D:\unity\EAP_Unity_Consumer\Assets\EAP\Trees\*.prefab` 两个文件 → 跑
`--unity-check --unity-verify-only`（跳过导入，只读回）：

```
NEG EXIT=1
[2/4] Prefab 存在 → FAIL
[3/4] 贴图读回 → FAIL（applied=None）
[4/4] bounds/triCount → FAIL（triCount=0 want=3370/3505，bounds 缺失）
```

再跑完整 `--unity-check` 恢复 → **4/4 PASS**，prefab 数恢复为 2。

> 方法论确认（与 TRAE 报告一致）：**凡是有自愈能力的前置步骤（导入会重建产物），反向验证必须绕过它**（`--unity-verify-only`），否则删掉产物也会被导入阶段重建、断言又 PASS——这正是上一轮「持久化状态导致假 PASS」的同类问题。
